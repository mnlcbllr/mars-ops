# MARS-OPS: current limitations

- **Research model, not safety certification.** Resource coefficients, slope thresholds, activity durations and priorities are user-defined assumptions. Orbital data does not resolve all surface hazards or establish actual astronaut traversability.
- **One local region and one instrument.** The bundled Jezero crop contains HiRISE elevation and registered imagery, not a global Mars map or a multi-instrument integration. Registration offsets and processing notes are recorded in the dataset manifest.
- **Discrete solver scope.** The default `ExactSubsetDp` solves site selection and visit order exactly for the routed leg table at minimum activity durations, then allocates dwell time with the shared greedy extension. It is not an exact continuous-time optimizer. A 2.5 s wall-clock budget abandons the subset search and falls back to `GreedyPlanner`; neither solver has a statistical superiority claim. On the bundled scenario both produced the same measured plan, while a unit fixture shows the subset search avoiding a locally attractive insertion.
- **Simulation is a drill, not a forecast.** The stateful simulation advances along the planned route and charges the declared model. Events are injected inputs, not observations or predictions. Replanning snaps the starting point to the planning lattice, uses a zero-overhead remaining model because the EVA overhead was already spent, and can report `INFEASIBLE` when no modeled return exists. Time and resource losses do not model astronaut health, weather, dust storms, radiation or hardware failure.
- **User-authored scenarios.** Missions start with no candidate sites; the user places each candidate on the map (only known terrain within the slope limit is accepted) and can edit its coordinates and activity settings, along with the base, budgets and model coefficients. **Save plan** writes the scenario without a result to `Documents/MARS-OPS/plans`, and plans saved for the open dataset can be reloaded. Scenario import from arbitrary files, dataset switching and arbitrary data import are not implemented. Export a solved report to retain its selected scenario.
- **Science layer blocked.** No archived `datasets/_source`, `AGENT_HANDOFF.md` or external `SHA256SUMS.txt` is present in this checkout. A CRISM, THEMIS, MEDA or PIXL layer was therefore not added: none of those products could be spatially verified against the packaged HiRISE crop. No science overlay, mineral score or radiation field is invented.
- **No job cancellation/progress stream.** Planning runs off the UI thread; scenario edits and export are locked until the request finishes. Long-running jobs cannot yet be cancelled from the UI.
- **Finite-resolution views.** The 3D view uses every fourth elevation sample at true vertical scale and requires WebGL. It uses the same planning outputs as the rest of the app.
- **Verification scope.** Frontend state/presentation tests, Rust unit tests and real-dataset integration tests exist. Browser IPC mocks do not replace native desktop end-to-end testing. Release installers and clean-machine/cross-platform behavior have not been verified here.
